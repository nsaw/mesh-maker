# ATC Tool Change Chain — Desktop MAX ATC V2 (`&ATC = 7`)

Verified against the live files on the shop laptop 2026-08-05, plus ShopBot's own
`Tool Change File calls.pdf` and `ATC File changes for PRS4 2017 11 06.pdf` in
`C:\SbParts\Custom\ATC\`.

**Read this before touching anything ATC-related, and prefer it over the shipped PDFs where
they disagree — the PDFs are older than this machine.**

---

## The `&ATC` value is the gate for everything

`&ATC = 7` on this machine, set at `C:\SbParts\Custom\my_variables.sbc:119`.

The 2017 PRS4 PDF says the options are "0 for manual toolchange machines, 1 for PRS3 and
earlier ATC machines and 2 for PRS4 ATCs". **That document is stale.** The live
`Custom89.sbc` branches on 1, 2, 3, 4, 6 and 7, and 7 routes to a `DT_ATC2_PATHS` block that
did not exist in 2017. Do not reason about this machine from the PDF's three-value list.

For `&ATC = 7` the chain resolves to:
- `&ATC_folder_path = C:\SbParts\Custom\ATC\`
- `&ATC_local_data_path = C:\SbParts\Custom\ATC_Local_Data\`
- `&ATC_Run_ATC = <folder>DT_ATC.sbp`
- `&ATC_Check_Status = <folder>DT_ATC_check_status.sbp`
- `&ATC_Writer = <folder>ATC_Write_Tool_Variables.sbp`

Machine geometry for `&ATC = 7` (`DTMATC2` block of `ATC_Settings.sbc`) includes
`&Transit_Height = -1`, `&ZUP = 0.125`, `&ATC_clipSafe = -1.75`, `&firstClipX = 39.75`,
`&firstClipY = 5.125`, prox switches all on input 3, tool sensor on 7, drawbar sensor on 8.

## The call graph

Custom command files live in `C:\SbParts\Custom\` as `Custom<N>.sbc` and are invoked as
`CN, <N>` from a part file or the console, or as `C#,<N>` from inside another `.sbc`.

```
C9  (toolchange from within a part file)  ->  Custom9.sbc
      C#,89   -> Custom89.sbc   sets &ATC_folder_path and all &ATC_* file paths
      C#,90   -> Custom90.sbc   -> FP my_variables.sbc  (defines &ATC)
      FP,&ATC_Run_ATC           -> DT_ATC.sbp
                                     ATC_Load_All_Values.sbp
                                     ATC_check_status.sbp / DT_ATC_check_status.sbp
                                     ATC_Write_Tool_Variables.sbp
                                     ATC_restore_settings.sbp
                                     C#,88 -> Custom88.sbc  (speed limits)

CN,1   manual tool change from input box -> ATC_change.sbp
CN,78  Print ATC Status  -> body is literally `FP,&ATC_Check_Status`
CN,79  MAX ATC2 Change ToolBar
CN,72  ATC Zero Tools In Rack        CN,73  ATC Get Plate Offset
CN,74  ATC Calibrate Tools In Rack   CN,77  ATC Set fixed Z plate position
CN,88  speed variables               CN,89  ATC paths
CN,90  loads my_variables.sbc        CN,91  unit-error message file
```

`ATC_tool_variables.sbc` in `ATC_Local_Data\` holds the per-tool Z offsets
(`&Tool4_Z = -2.202` etc), `&PlateOffset`, and `&ToolIN`. **It is rewritten on every
toolchange** — its mtime is a reliable timestamp for when a run's first `C9` executed.
Never hand-edit it; it is regenerated by `ATC_Write_Tool_Variables.sbp`.

## The ordering bug, and why part files paper over it

`Custom9.sbc` calls `C#,89` **before** `C#,90`:

```
C#,89     <- needs &ATC, which is not defined yet
C#,90     <- this is what defines &ATC
```

`Custom79.sbc` has it the right way round (`C#,90` then `C#,89`). `Custom9.sbc` does not, so
it cannot self-heal. The only reason toolchanges work is that the Vectric post writes
`CN, 90` at **line 18 of every part file**, before the first `C9` at line 28.

`Custom89.sbc` opens with:

```
IF &ATC = 1 THEN GOTO ATC_PATHS
...
IF &ATC = 7 THEN GOTO DT_ATC2_PATHS
GOTO ENDTHIS
```

With `&ATC` undefined it falls straight through to `ENDTHIS` and **sets no path variables at
all**.

## Recognizing an unresolved SBP variable

When a path variable is unset, SB3 takes the bare token and resolves it against the **current
parts directory** — `FS` parameter 1, which follows whatever folder you last loaded a part
file from. The failure looks like this:

> ATC status tried to open `C:\CNC\jobs\26-APPLE-TABLE\sbp-toolpaths\ATC_Check_Status.sbp`

**The tell is the capitalization.** `ATC_Check_Status.sbp` matches the *variable name*
`&ATC_Check_Status`, not either real file on disk (`ATC_check_status.sbp` or
`DT_ATC_check_status.sbp`). Any time a missing-file path echoes a variable's name in a job
folder, the variable is unresolved — the path setting is not the problem.

**`FS` pointing at the job folder is correct, documented behavior. Do not "fix" it.** ComRef:
the parts directory changes during the file-selection process of `[FP]` or `[FE]` and "stays
in effect until altered by [FS] or another change made during file selection." Resetting it to
`c:\SbParts` lasts only until the next job is loaded, and points the file browser away from
where the work lives.

The real fix is to make the ATC variables load: run any Vectric-posted part file (they all
carry `CN, 90`), or issue `CN, 90` at the console when no file is loaded.

## Menu labels are not a map of what exists

The `Custom [N]umber` menu shows a description drawn from the **first comment line** of each
`.sbc`. Files whose first line is a bare `'` show blank and look unassigned. `Custom88`,
`Custom89`, `Custom90`, `Custom91` and `Custom9` all show blank and all contain working code.
Never conclude a custom number is unused because the menu shows nothing next to it — check
`C:\SbParts\Custom\Custom<N>.sbc` on disk.

## Operating procedures, from the ATC V2 manual (SBG00609, May 2023)

The three setup routines run in a fixed dependency order. Getting the order wrong produces
wrong Z depths that look like a CAM problem.

**`CN,74` — Calibrate Tools In Rack.** First, and only when clip positions have moved.
**Remove every tool holder from the toolbar and the spindle first.** It auto-homes via `C3`,
stops above clip 1, then prompts for three things: an empty tool holder (no tool, no collet,
no collet nut) in the spindle, a second empty holder clipped into clip 1 **pull-stud pointing
down**, and the grounding clip attached to both that pull stud and the edge of the fixed
Z-Zero plate. Four probing moves follow. Only clip 1 is probed — clip spacing is manufactured
consistent, so the rest are derived. Afterwards it parks over the fixed Z-Zero plate and opens
the keypad so you can nudge that position; Escape saves. New X, Y, Z values print to the
message screen.

**`CN,72` — Zero Tools In Rack (measure tool lengths).** Requires calibration first. Prompts
for a tool number, or **0 to measure all**. Fully automated: no grounding clip, no plug-in
plate, it touches off on the fixed plate. Re-run any time a bit is added **or replaced with
the same kind of bit**.

**`CN,73` — Get Plate Offset.** Measures Z between the fixed Z-Zero plate and the cutting
surface. **Must be re-run every time the spoilboard is resurfaced or replaced**, because
surfacing lowers that reference. Measure onto the **spoilboard itself, never onto material
sitting on it**. Homes with `C3`, opens the keypad to pick a spot (near centre is best), then
you plug in the Z-Zero plate and attach the grounding clip.

**`C5` — Spindle warmup, 9 minutes.** Run it whenever the machine has sat idle more than an
hour. Skipping it risks premature spindle failure. Desktop models have no automatic speed
control during warmup, so step RPM by hand: 12,000 for 3 min, 15,000 for 3, 18,000 for 3.

**`C3`** is the XYZ homing routine. `JH` jogs to origin.

### Input switch map (matches `ATC_Settings.sbc`)

| Input | Meaning |
|---|---|
| 1 | Z-Zero plate contact |
| 7 | Tool clamped in spindle (`&Tool_Sensor = 7`) |
| 8 | Drawbar open (`&DrawBar_Sensor = 8`) |

Drawbar check: hold the green button at the back of the gantry, air rushes and input 8 lights;
insert a holder and release, input 7 lights and 8 goes out.

### CAM side

Tool numbers in the design software **must match the physical clip position** — that number
drives selection. ShopBot recommends a tool-database group named "Tool Changer" or "ATC".
This machine posts with `ShopBot TC (inch)(*.sbp)` from `PostP\postp.ppdb`; the legacy
`ShopBot(inch)(Toolchange)w/speed(*.sbp)` also emits `C9`. The Aspire log names the post that
produced a file (`aspire-installation-layout.md`). Shank insertion into the collet should be at
least 0.75".

### Beyond tool 7

Tools 8-28 work without being on the bar. Measure with `CN,72` — the spindle parks centrally
and prompts for a hand insert. During a cut, an off-bar tool pauses the file and prompts.
Extra toolbars are selected with `CN,79`: bar 2 = tools 8-14, bar 3 = 15-21, bar 4 = 22-28,
bar 1 = the standard 1-7. Past measurements survive a bar swap.

Oversized stock: the toolbar comes off — unplug the **orange connector** first, then the
bolts. A sensor detects its absence and toolchange falls back to manual insertion. With the
bar off there is no fixed Z-Zero plate, so `CN,72` switches to the plug-in plate and prompts
you to position over bare spoilboard. Those measurements stay valid when the bar returns.

### ATC symptom table, from the manual

| Symptom | Cause and fix |
|---|---|
| Spindle will not release the holder | A holder left in overnight sticks; the manufacturer says never leave one in. Push it out with the 17mm wrench. Also confirm the regulator is supplying a full **90 psi** — low air will not open the drawbar completely |
| Holders miss the clips | Re-run `CN,74` |
| Depth of cut inconsistent between bits | Re-run `CN,72` |
| Cutting in the wrong place from the start | Run `C3` first. Aspire's default origin is bottom-left of the cut area |
| Was fine, then went wrong mid-cut | Lost steps from an obstacle or excessive feed. The motors cannot recover position on their own — re-home with `C3`. No damage done |

To see what tool the software believes is loaded, read `&ToolIN` in
`C:\SbParts\Custom\ATC_Local_Data\ATC_tool_variables.sbc`.
