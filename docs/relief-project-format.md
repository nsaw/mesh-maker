# Procedural relief project format

`.mcproject` version 1 contains procedural Voronoi relief only. It does not promise to reconstruct images, imported relief masters or Drape figures. Those source kinds are rejected explicitly. The Noise relief Plan view provides site editing and Save/Open project controls.

The root object contains exactly `format`, `version`, `kind`, `generation`, `params`, `query` and `sites`. The identifiers are `meshcraft-project`, version `1` and kind `procedural-voronoi-relief`. `generation` must equal the application's current generation payload version. Unsupported versions fail rather than loading under changed noise semantics.

`params` contains every generation request field except runtime `reliefRevision` and the separately stored `reliefSites`. It includes actual resolution, seed, dimensions, stock, smoothing and watertight state. Numbers are finite and bounded by the format's explicit parameter table. Seed retains every finite binary64 value; the producer separately records its effective uint32 seed. The generation-23 request includes invert, cell jitter and cell metric, and excludes removed noise exponent, contrast and sharpness fields. Booleans and enums retain their types. A numeric negative zero uses the string marker `-0`, decoded only in a numeric field. Unknown, missing, coercible or silently clamped values are not accepted.

`query` records the producer's effective metric and warp, with implementation identity `meshcraft-relief-query/2`. The owner policy is `exact-represented-metric-stable-id-v1`, with exact represented cos/sin/scale metric comparisons and lower stable IDs at exact ties. An active warp includes copied immutable permutation and gradient metadata from the actual Fisher-Yates runtime kernel. An inactive warp records a null kernel. Parsed values must exactly match the production descriptor for the saved parameters. Any change to the Simplex/warp algorithm must advance this identity as well as the generation version. This descriptor is an owner-query contract, not a certificate that a warped cell graph can be exported.

`sites` stores a count, base64 `xyFloat64LE` coordinates, strictly increasing uint32 stable IDs, binary pin flags and the original pre-cap count. Coordinates use explicit little-endian IEEE Float64 bytes, preserving negative zero and every retained bit. The maximum count is 4096. Existing coincident producer sites retain distinct IDs and order, with lower-ID ownership at ties; validation reports their count and never merges them. Manual move/add rejects a newly coincident coordinate. Pinning belongs to each site, so a newly added unpinned site can follow polar sites in ID order. Retained site IDs never change when another site is erased. Adding after ID 4294967295 allocates the lowest unused uint32 ID and inserts it in sorted order without changing retained traits.

Documents are limited to 1,000,000 encoded bytes and 4,194,304 generation nodes. A source beyond the node limit must use a smaller requested grid before saving this format. Project files are lossless.

Approximate share links carry at most 1000 sites. Their versioned `_sites` object stores explicit little-endian Int16 coordinate pairs in hundredths of an inch, uint32 stable IDs and binary pin flags. Board-edge positions round inward when the board dimension lies between hundredths. Each coordinate changes by less than 0.01 in. IDs and pins remain exact. Copy Link reports the coordinate precision and refuses oversized or coincident quantized sets, directing the user to Save project. It never copies a procedural replacement for an unsupported frozen set. Existing coincident producer sites can still be saved losslessly in a project.

Cell links use the URL fragment so coordinate data is not sent in the HTTP request target. Decoding validates the count before allocating coordinate arrays, canonical base64, exact fields, bounds, IDs, pins and duplicate coordinates. A malformed frozen-site link rejects the entire configuration and shows a notice. Runtime revisions are assigned afresh. The encoded configuration is bounded before base64 decoding. `npm run test:relief-link` exercises these limits and the complete source round trip.

Frozen-site queries bound bucket allocation and empty-bucket searches by the retained population, including tightly clustered, sparse, collinear and coincident coordinates. This changes indexing work without moving sites or changing distance arithmetic and lower-ID ties. Dynamic procedural placement retains its original spacing while its population grows.

`NoiseGeneration.completedSource(params)` returns a copied snapshot plus revision only for the current completed full surface. Preview, pending, stale, failed and cancelled requests provide no authoring source. Published producer snapshots retain private arrays and return copies to readers. History retains its own detached documents, so editing a returned copy or transferring its buffers cannot mutate a checkpoint. One gesture creates one undo checkpoint; the history keeps at most 50. Cancel restores the preceding document and retires the intermediate revision. Undo, redo and accepted import receive fresh monotonic revisions.

Generate and Apply layout ask before regenerating any active frozen cell layout, including a freshly frozen, saved or imported layout. Cancel leaves the applied source, pending controls and Undo/Redo history unchanged. Confirming replaces the cell positions from the pending settings. Undo restores the preceding source and its pending settings. This protection does not depend on whether the document has unsaved changes.

Import parses and validates into detached data, awaits a supplied asynchronous geometry preflight, then checks the latest import intent and captured revision before replacing source settings/sites in one history operation. Invalid, failed or superseded imports leave the active source and history unchanged. An accepted import becomes the saved checkpoint. Browser callers must provide a worker preflight rather than run heavy generation on the main thread. `preflightReliefProject` is a synchronous Node helper for validation. Save captures both bytes and revision, and only a matching completion may clear dirty.

No third-party persistence or geometry code was copied for this format. `npm run test:relief-project` checks its codec, producer identity, history, stale-import, buffer ownership and native class parity contracts. The editor, approximate links and graph/DXF paths have separate tests and native acceptance gates; the project codec checks alone do not validate those paths.
